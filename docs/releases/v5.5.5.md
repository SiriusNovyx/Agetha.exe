# Agetha Mod v5.5.5

Version 5.5.5 introduces Fast Mode 2.0: a reversible on-disk performance
profile paired with request-aware runtime budgets. It is an intentional release
of the SiriusNovyx fork and does not copy or adopt an upstream version number.

## Platform support

Official release targets are Windows 10/11 x64, Windows 11 ARM64/Snapdragon
through x64 Python under Prism, and Linux desktop environments covered by the
existing Linux paths. Windows and Linux share a Python 3.13 GitHub Actions
matrix, with additional platform-specific Fast Mode and desktop-path smokes.

macOS is retired and unsupported with this release. Historical macOS fallback
code and previously published GPLv3 source remain available, but macOS receives
no release testing, compatibility fixes, or user support.

## Reversible configuration profile

When `FASTER_MODE = yes`, Agetha atomically records the user's existing values
in `memory/fast_mode_snapshot.json`, then writes these approved temporary values
to `config.txt`:

| Setting | Fast value |
|---|---:|
| `AI_MAX_TOKENS` | `220` |
| `HISTORY_LIMIT` | `3` |
| `MEMORY_CHARS` | `300` |
| `EPISODIC_PROMPT_LIMIT` | `3` |
| `AI_TEMPERATURE` | `0.65` |
| `AI_TOP_P` | `0.90` |
| `ENABLE_STREAMING` | `yes` |
| `ENABLE_COMPANION_STATS_CONTEXT` | `no` |
| `DATETIME_INCLUDE_SECONDS` | `no` |
| `SCREEN_POLL_INTERVAL_SEC` | `180` |
| `OCR_MAX_DIMENSION` | `1920` |
| `OCR_PREPROCESSING` | `basic` |
| `OCR_FORCE_REFRESH_SECONDS` | `30` |

The snapshot uses schema version 1 and profile version 1. It stores only the
managed key name, whether the key was present, its original textual value, the
forced value, and—after a detected manual edit—an optional restore preference.
It never stores `.env` data, credentials, OCR text, memory, or a copy of the
complete configuration.

Turning Fast Mode off restores or removes only those managed settings. Comments,
ordering, blank lines, unknown keys, and unrelated settings remain in place.
The snapshot is removed only after the restored configuration is written and
validated successfully. If only snapshot cleanup fails, the restored settings
remain committed and the validated snapshot is retained so Medic or the next
startup can retry cleanup safely.

If a managed value is changed to a third value while Fast Mode is active, Agetha
treats that as a new user preference. Fast Mode remains effective for the active
session, then preserves the new value when the profile is disabled. The original
snapshot value is not overwritten.

If that manual value is not valid for the typed setting, restoration stops
without deleting the snapshot. Correct the value and set `FASTER_MODE = no` in
`config.txt`, then retry from Medic Checker; Agetha does not silently replace an
invalid preference.

## Startup and crash recovery

Startup reconciliation runs before runtime settings are cached. Repeated starts
do not snapshot already-forced values. A valid active snapshot is checked and
managed drift is repaired without replacing original values. A valid snapshot
with `FASTER_MODE = no` is restored automatically.

A corrupt snapshot while Fast Mode is off is quarantined without changing
`config.txt`. A corrupt snapshot while Fast Mode is on fails closed: Agetha does
not manufacture new originals from possibly forced values. Medic Checker shows
the health state, offers confirmed restoration when metadata remains valid, and
never silently deletes a valid snapshot. If the user declines a required Fast
Mode reconciliation, Medic still launches Agetha with a process-only, one-launch
signal that skips startup reconciliation; the declined action remains pending.

Mutating profile operations use a persistent cross-process lock with 75 ms
retry and a four-second timeout. The lock is opened without following links
where supported, checked against its path identity, and reused when it already
exists but is unlocked. After acquisition, the config, memory directory,
snapshot, and lock are all revalidated. Unsafe substitution returns
`unsafe_path_state`; contention returns `profile_busy` without changing the
config or snapshot.

If replacement may have completed but verification was interrupted, the result
is `verification_pending`. Caches are invalidated, recovery metadata is kept,
and the next reconciliation derives state from disk rather than replaying a
cached activation/restoration. See
[Fast Mode security and recovery](../fast_mode_security.md).

## Adaptive request profiles

Fast Mode uses separate internal budgets for ambient events, commands, normal
conversation, tool results, and explicit deep analysis. Ambient requests carry
no chat history, command requests retain at most two recent turns, and normal
user requests retain at most three. Tool-result and deep-analysis requests may
use the saved pre-Fast output ceiling so document and OCR analysis are not
artificially truncated. Those profiles use a complete-analysis segment rule,
retain the final assistant answer for later follow-up, and replace raw tool or
OCR input with a compact synthetic history marker.

An unchanged, empty, excluded, own-window, or repeated ambient scan is handled
locally in Fast Mode when there is no pending dream or status observation.
Meaningful new OCR events still reach the configured provider. The same profile
selection and output controls apply to Groq, OpenRouter, and local Ollama.

## Safety and privacy boundaries

Fast Mode never changes provider selection, API keys, command execution or
confirmation settings, protected-process rules, OCR exclusions/redaction,
deep-OCR routing, long-term memory, or any external-service opt-in. Deep OCR
remains explicit-only and command guards are unchanged.

The override allowlist is validated before activation, snapshot validation, and
migration. Secret, provider, permission, confirmation, protected-process,
OCR-privacy, remote-OCR, and consent settings fail closed if introduced. Compact
prompts preserve the command safety kernel, label OCR/web/document/memory/tool
data as untrusted, prohibit pre-execution success claims, and refuse deep OCR
outside a new direct user request.

Atomic config/snapshot writes use exclusive same-directory temporary files,
file flush/fsync, replacement, and POSIX directory fsync. POSIX files are
user-only. Windows files inherit the per-user installation directory ACL;
portable `chmod` is not represented as Windows ACL hardening, and the snapshot
contains no secrets.

## Recovery tooling and audits

Medic Checker retains separate, confirmed `status`, `reconcile`, and `restore`
operations and handles busy or ambiguous verification states without printing
stored values. Linux/direct-Python users have equivalent commands:

```bash
python -m agetha.core.fast_mode_profile status
python -m agetha.core.fast_mode_profile reconcile
python -m agetha.core.fast_mode_profile restore
```

Exit codes are `0` healthy/completed, `1` recoverable action required, `2`
invalid/unsafe/failure, and `3` profile busy. Structured local audit events
record transition names, statuses, versions, platform, counts, and changed key
names only; audit failure cannot block recovery.

## Upgrade notes

Existing configurations need no manual migration. On the first v5.5.5 launch,
`FASTER_MODE = no` leaves the configuration unchanged. If it is already `yes`,
the current unforced managed values are captured before the profile is applied.
Use the dashboard to disable the profile normally, or Medic Checker if recovery
is required after an interrupted write.

## Validation contract

The release workflow runs the full unit suite, repository compileall, focused
profile/runtime/Dashboard/Medic/security suites, shared import smoke, and
platform-specific recovery tests on `windows-latest` and `ubuntu-latest`.
Windows parses `Medic_Checker.ps1` and runs reparse/identity/timeout tests;
Linux runs actual symlink, POSIX permission, `fcntl`, CLI, and mocked desktop
fallback coverage. No job uses provider keys, a physical display, real
Tesseract, or remote OCR.

Hosted Windows runners are x64, so a manual Surface Pro/Windows ARM Prism test
remains required. Exact local and CI results belong in the final PR/release
report rather than being assumed from this document.
